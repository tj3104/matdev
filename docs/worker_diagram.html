MatSim 実行役の仕組み

ジョブを始められるのは実行役だけです。今は MatSimApp が実行役を兼ねているので、切ると次のジョブを始める役がいなくなります。動いている gpumd は止まりません。

役割の分担

今の状態

今のまま MatSimApp を切ると

実行役を独立させると

# 1. 先に別の端末で起動する（MatSimApp が動いている間は待機）
~/.venv/gpumd312/bin/matsimapi --data-dir ~/matsim/data worker

# 2. そのあと MatSimApp を止める。5 秒以内に引き継ぐ

実行役になれるもの

プロセス実行役がいるとき実行役がいないとき
MatSimApp待機引き継ぐ
matsimapi worker待機引き継ぐ
ジャービス (matsimapi mcp)登録だけ状態確認や投入のときに実行役を裏で起動する

先に worker.lock を取ったプロセスが実行役になる早い者勝ちです。実行役がいない状態でも、ジャービスに状態を聞けば再開します。ここの動作はコードで確認したもので、切り替えを実際に試してはいません。
